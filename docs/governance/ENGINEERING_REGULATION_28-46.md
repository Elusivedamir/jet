28. Выбор оптимального технологического стека

До начала написания основного кода проведи технический анализ и выбери оптимальный технологический стек для Jetson Messenger.

Не выбирай язык программирования, фреймворк, базу данных или инфраструктуру только потому, что они популярны или хорошо знакомы AI-модели.

Выбор должен учитывать:

- назначение и сложность Jetson Messenger;
- поддерживаемые платформы;
- производительность при обмене сообщениями;
- безопасность;
- масштабируемость;
- надёжность;
- стоимость разработки и дальнейшего сопровождения;
- доступность специалистов;
- зрелость экосистемы;
- качество документации;
- наличие готовых и проверенных библиотек;
- совместимость компонентов;
- возможность независимой дальнейшей разработки без AI.

Рассмотри обоснованные альтернативы для каждой существенной части системы.

Для каждого кандидата указывай:

1. Преимущества.
2. Недостатки.
3. Ограничения.
4. Влияние на производительность.
5. Влияние на безопасность.
6. Сложность разработки.
7. Сложность сопровождения.
8. Совместимость с другими компонентами.

Не придумывай результаты тестов и сравнений.

Если выбор зависит от ещё не согласованных платформ, нагрузки или бюджета, указывай это явно.

Не фиксируй окончательный технологический стек до анализа необходимых требований. Предварительные варианты обозначай как предварительные.

Результатом должен стать документ «Технологический стек Jetson Messenger» с обоснованием каждого выбора.

35. Работа с базой данных и целостностью данных

Проектируй базу данных с учётом корректности и сохранности информации.

Обязательные правила:

- Определяй типы данных осознанно.
- Используй ограничения целостности там, где они необходимы.
- Продумывай индексы на основании предполагаемых запросов.
- Не допускай необоснованного дублирования данных.
- Контролируй связи между сущностями.
- Используй транзакции для операций, которые должны выполняться целиком.
- Предусматривай обработку конфликтов одновременного изменения данных.
- Выполняй изменения структуры базы через миграции.
- Проверяй возможность отката миграций либо безопасного восстановления.
- Не удаляй и не изменяй существующие данные без анализа последствий.
- Проверяй производительность тяжёлых запросов.

Не создавай индексы и ограничения случайным образом. Объясняй их назначение.

Особенно внимательно проверяй сохранность сообщений, пользователей, клиентских карточек, согласий на рассылки и платежных записей.

- Перед значимыми изменениями проверяй текущее состояние репозитория.
- Не перезаписывай чужую работу.
- Не удаляй существующие изменения без разрешения.
- Разделяй независимые задачи на отдельные изменения.
- Используй понятные сообщения коммитов.
- Не помещай в коммиты секреты и реальные пользовательские данные.

- Перед слиянием проверяй тесты и сборку.
- Не отправляй заведомо неработающий код в основную ветку.

Для крупных изменений сначала создавай отдельную рабочую ветку.

Каждый существенный коммит должен отражать понятную логическую задачу.

- не переписывай без анализа;
- найди точки вызова;
- проверь зависимости;
- выясни, какие данные он обрабатывает;

Не маскируй неизвестность догадками.

Если обнаружен непонятный фрагмент AI-сгенерированного кода, объясни его назначение простым языком или замени более понятной реализацией после проверки функциональной эквивалентности.
